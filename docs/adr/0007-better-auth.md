# ADR-0007: Better Auth for accounts and sessions

- **Status:** Accepted
- **Date:** 2026-11-20
- **Task:** P0-ENG-05

## Context

We need sign-up and sign-in for developers, contributors, reviewers, senior reviewers and admins (US-01, US-18, US-24, US-26). The web app is Next.js; the API that enforces roles is Go. The candidates were Better Auth and Auth.js.

| Criterion            | Better Auth 1.7                                 | Auth.js 5 (beta)                                                                              |
| -------------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Licence              | MIT                                             | ISC                                                                                           |
| Maintenance          | Active, releases weekly                         | Now maintained by Better Auth; v5 still beta. The project recommends Better Auth for new work |
| Email and password   | Built in                                        | Discouraged; needs custom code                                                                |
| Roles                | `admin` plugin: role field, bans, impersonation | Hand-written                                                                                  |
| Sessions in Postgres | Yes, `session` table, readable from Go          | Yes with an adapter; JWT by default                                                           |
| Schema control       | Table and field names configurable (snake_case) | Fixed by adapter                                                                              |

## Decision

Use **Better Auth** in `apps/web`, backed by the same PostgreSQL database.

- Better Auth owns `users`, `sessions`, `accounts` and `verifications`. Its migrations are generated by its CLI and committed as goose migrations, so goose remains the only migration runner.
- Global roles use the `admin` plugin's `role` field: `developer` (default), `contributor`, `admin`.
- Per-language rights (reviewer, senior reviewer) are not global roles. They live in our own `reviewer_approvals(user_id, language_code, level)` table, because approval is per language (CON-2, DQ-3).
- **Go validates sessions itself.** The web app forwards the session token in `Authorization: Bearer`. Go looks the token up in `sessions`, checks expiry, and loads the role and approvals. No call to the web app is needed, and no shared secret beyond the database.
- Developer API keys (DEV-1) are separate from sessions and are decided in P1-API-11.

## Consequences

- One auth library, one database, and no extra service to run.
- The Go API depends on Better Auth's session table shape. A test in Go reads a session that Better Auth wrote, so a library upgrade that changes the shape fails CI.
- Social sign-in can be added later through Better Auth providers without changing Go.
